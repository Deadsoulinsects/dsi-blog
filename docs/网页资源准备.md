# 网页资源准备

这一步把已匹配的 Obsidian 原始附件转换为可长期交付的静态资源。它独立于同步、prebuild、Admin 原图预览和远端发布，不改源 Markdown 或附件。

## 使用

先准备本地 Sharp（`npm ci`）以及包含 libx264 和 AAC 的 FFmpeg / ffprobe。FFmpeg 可放在仓库外；构建 GitHub Pages 不需要它。

```powershell
npm run media:prepare -- `
  --note "D:\GitHub\cloud-storage\obsidian\思考与实践\2026生态大实习\工作日记.md" `
  --source-root "D:\GitHub\cloud-storage\obsidian\思考与实践" `
  --id "工作日记" `
  --ffmpeg "D:\script\DSI-media-tools\ffmpeg-9.0.2-essentials_build\bin\ffmpeg.exe" `
  --ffprobe "D:\script\DSI-media-tools\ffmpeg-9.0.2-essentials_build\bin\ffprobe.exe"
```

也可以使用 PATH 或 `FFMPEG_BIN` / `FFPROBE_BIN`。`--source-root` 是引用路径的起点：引用 `2026生态大实习/picture/...` 时应提供 `思考与实践`，不是 picture 子目录。`--id` 是稳定的内容身份；文章改标题时不要随意换 id。

`--store-root <目录>` 用于独立 sandbox，结构仍为 `public/media` 和 `src/data/media-manifest.json`。源目录与资源存储目录必须分开。

```powershell
npm run media:prepare -- --orphans
npm run media:verify
```

## 唯一契约

- `src/shared/content/frontmatter.mjs`：Admin 和本地命令共同拆分正文。
- `src/shared/content/media.mjs` / `gallery.mjs`：引用发现、严格路径与图库语义。
- `src/shared/content/web-media.mjs`：网页交付策略、manifest 校验及公开资源 resolver。
- `scripts/media/encode.mjs`：Sharp / FFmpeg 本地文件系统适配器。
- `scripts/media/prepare.mjs` / `store.mjs`：内容哈希、增量和事务提交。

浏览器原图预览仍使用 File/object URL，不在浏览器里复制一套转码策略，也不引入 FFmpeg WASM。

## 图片策略

静态 JPEG、PNG、WebP、AVIF 转 WebP；480 / 960 / 1600 是宽度目标，最大高度 2400，不放大、不裁切，实际尺寸相同的档位合并。质量 82、effort 5。方向烘焙、sRGB 转换、移除 EXIF/GPS，PNG 使用无损编码以保留文字和透明度。

不额外生成 JPEG fallback 或 AVIF：现代浏览器已经支持 WebP，多套编码会扩大 Git 二进制与准备时间。SVG、动画和其他未验证格式明确失败，不把动画静默变成首帧。

## 视频策略

已标记 SDR 的 H.264 / HEVC MP4 转 H.264、yuv420p、AAC 128k、CRF 23、medium、最高 1920×1080 / 30fps，保留时长及音频，不放大。MP4 faststart，另生成不超过 960px 的 WebP 首帧海报。

没有音频的源仍无音轨。HDR、未知色彩与非方形像素明确失败；没有未经验证的自动 HDR tone mapping。视频仍会有有损降采样；原始 4K / 60fps 文件留在 Obsidian。

## 映射

`media-manifest.json` 保存在源数据目录，不对外发布私人绝对路径。形状为：

```text
documents[稳定内容 id].resources[规范化完整源路径] → assetId
assets[assetId] → 源 SHA-256 / bytes / 尺寸 / 编码配方 / 网页 variants / poster
recipes[配方 SHA-256] → 实际参数与工具版本
```

assetId 由类型、源内容 SHA-256、配方 SHA-256 决定；产物 URL 为 `/media/<产物 SHA-256>.webp|mp4`。完全相同的源内容跨文件、跨文章只编码和保存一份。相同产物内容也合并，源改名不改变资源 URL。

`resolveWebMedia(manifest, id, reference, BASE_URL)` 返回 src、srcset、宽高或视频 poster。严格使用完整源路径，无 basename 回退；保存的 URL 不绑定域名，并支持 Astro 子路径部署。

## 增量与事务

每次实际读取源内容 SHA-256，不信任 size/mtime。源、配方以及所有派生文件哈希都一致时复用；不改文件 mtime，不重写相同 manifest。工具版本升级会使相关编码配方失效；这会新增二进制，升级前应检查预算。

缺失或损坏的产物重新生成。匹配全部完成、预算通过、源快照再次确认后才提升资源，最后原子替换 manifest。转换失败不替换旧有效清单。异常崩溃可能留下未引用文件，由孤儿报告指出。

`.media-work/lock` 排除并发写入；进程崩溃遗留 lock 时，确认对应 PID 已不在运行后再人工移除，命令不会猜测并抢占锁。

## 体积与孤儿

- 单文件硬上限：20 MiB，低于 GitHub 单文件限制。
- 单文章建议：50 MiB；长篇图集超过时报告 warning。
- 单文章硬上限：80 MiB。
- 媒体目录硬上限：500 MiB，包括未清理孤儿和普通未管理文件。

GitHub Pages 的整体站点空间还包含 HTML、其他静态文件等；媒体预算不等于整个站点额度。输出 warning 不是发布许可，本步骤不发布文章。

重新准备同一 id 时替换其当前引用，其他文章引用仍受保护；不再被任意文章引用的历史 asset 不留在活跃 manifest，但物理文件保留并报告。报告仅是候选，不能证明旧部署、手写文章或外部分享没有使用 URL，因此不自动删除。

人工清理前检查正式内容、部署与外部引用，并保存当前 manifest。删除当前文件只缩小 working tree / Pages 产物，不缩小 Git 历史。本工具不做历史重写、Git LFS、数据库或媒体服务。频繁重转码和持续添加大视频会积累历史，达到预算时必须重新评估素材选择或存储方式，不能自动绕开限制。

## 当前边界

当前提供可重跑的准备命令、共享协议和正式 Astro 富媒体渲染；未提供 Admin 一键转码 UI、上传或远端发布。simple-gallery 已确认的 layout / min-size / gap / corners / caption 语义不变。

## 正式文章接入

正文保留 Obsidian 图片、视频和 simple-gallery 原语法，不写回公开哈希链接。站点 frontmatter 用 `mediaId: 工作日记` 绑定清单中的稳定内容身份。

Astro remark 插件在构建时用共享引用分类、Gallery parser 和 resolver 生成图片 / 视频 / 图集 HTML；资源、映射或图库语法错误会让构建失败，而不是留下本地路径 404。普通未绑定文章继续使用现有 Astro Markdown 链。运行 `npm run media:verify-article` 验证构建适配器。

默认 Obsidian 发布目录不变。日记位于默认目录之外，显式更新它时执行：

```powershell
npm run sync:blog -- --file "D:\GitHub\cloud-storage\obsidian\思考与实践\2026生态大实习\工作日记.md"
```

`--file` 仅同步选定文件，保留仓库 frontmatter（包括 mediaId），正文从原文更新；`--dry-run` 可先检查。资源有变更时还需重新 `media:prepare`，随后运行既有 prepare/link normalization 和 `build:astro`。同步不转码，也不修改 Obsidian 原文。
