# DSI Admin

DSI Admin 是连接 Astro 博客工程与 Obsidian 笔记库的 Windows 桌面文章管理程序。正文仍在 Obsidian 编辑；程序负责元数据、草稿、预览、网页附件、检查、提交与发布。

当前版本：**0.1.3**。本轮安装包与实机验收状态见 [更新记录](./CHANGELOG.md)。产品定位和边界见 [产品介绍](./产品介绍.md)。

下述原笔记选择与迁移流程属于未发布源码更新，未重建安装包或修改已安装的 data。现有 0.1.3 安装版需要后续打包升级才能使用这些变化。

[版本验收记录](./验收记录.md) 区分开发环境、包内运行、真实工程和外部服务的验证范围。

## 安装与第一次连接

使用 Windows 10 / 11 x64 安装包。按当前用户安装，选择可写的独立目录，例如 `D:\Apps\DSI Admin`；不要安装在博客 Git 仓库或 Obsidian 笔记库内部。

安装版包含 Electron / Node、Git、FFmpeg、ffprobe、图像转换及 Astro 检查依赖，不需要另外安装工具或打开终端。

1. 打开程序，在工作区配置选择本地 DSI-blog 工程和 Obsidian 来源根目录。
2. 正式站地址填写实际博客 HTTPS 地址，不是 GitHub 仓库网页。
3. 填写 Git 提交身份或使用仓库已有身份，点击保存工作区配置。
4. 正式文章与本地草稿自动载入。未绑定源的正式文章需明确绑定原始 Markdown，不能仅凭同名猜测。
5. 需要 GitHub 发布时再保存具有相应仓库权限的凭据；本地导入、编辑和检查不依赖 GitHub 凭据。

凭据通过当前 Windows 用户的 DPAPI 加密，不回读到界面；换机器或用户后需要重新连接。当前安装包未代码签名。

## 日常工作

- 在自然目录中选择原始 Markdown 或目录树，按目录勾选后排除单篇，不再复制到“博客发布”。目录与待确认扫描默认排除“博客发布”和 `picture`；`picture` 只作为附件，不变成专题或文章。来源目录与网站专题可以分别维护。
- 按专题浏览、查找文章，在下方全宽面板编辑；功能板块可以折叠。正文预览使用共享渲染与 Gallery / Media 规则。
- 选择父专题或子专题后点击“编辑描述 / 置顶”，保存本地草稿；留空可清除介绍。一级专题可勾选为文章页置顶，只能置顶一个，重新选择会替换原置顶。文章页最多展示两个一级专题：置顶优先，其余按专题内最新文章的完成日期（含后代文章）自动补位并去重；未置顶、置顶无文章时按最近顺序展示，专题不足不造空位。日期相同时按专题名称排序。
- 描述与置顶设置可不选择文章而单独确认提交，或随所选文章一并提交。所有已保存的专题草稿加入精确差异，确认后才写入 `src/data/topics.json`；设置不改原文、专题路由或文章检查结果，不触发重新准备。取消置顶时选择当前置顶专题并取消勾选，再保存和提交。
- 标题、描述、完成日期、专题等字段自动保存到本地草稿，不回写原始笔记。日期来自 `completion_date`，缺失或无效时提示填写，不再自动使用当天或文件修改时间。旧 `pubDate` 仅在缺少完成日期字段时迁移。
- 已绑定原文的正文、作者元信息与附件变化触发准备；源笔记明确提供的字段更新草稿，站点 `mediaId` 等技术字段保留。新发现的 Markdown 保持待确认。
- `article-header-sync` 插件的受管头部在导入时移除，再由站点与预览独立渲染；标签与可选起止日期保留，原始笔记不变。
- 任务显示文章、触发原因、阶段和结果；技术错误可以展开查看。准备完成与“准备就绪”不同，元数据仍可能需要补齐。
- 多篇纳入或“准备所选文章”共用一个批次工程，统一整理链接和媒体清单，相同附件复用转换结果；整批只执行一次静态检查和构建。原文同步发现的多篇变化也合并准备。缺少信息或附件的文章单独记录，其余文章继续；整批检查失败时不标记为就绪。
- 当前版本已准备就绪时，打开或重读提交差异直接复用检查结果，不重复准备或构建；原文、附件、草稿或工程变化后需重新准备。提交前查看精确文件差异，输入自己的 commit 信息并确认。只有确认提交才写入正式文章、必要 manifest 和网页派生附件。
- 发布列出所有已提交而未推送的 commit，不夹带未提交草稿，也不支持选择性推送。程序不强推；上线确认绑定对应 SHA 的 Actions 和站点索引。

“未提交 / 已提交 / 已推送”描述当前版本；准备就绪和部署结果独立。站点结构展示本地文章的专题和稳定路径，不代表这些草稿已上线。

### 把已有文章重新绑定到原笔记

先比较原笔记与历史“博客发布”副本，两者可能各有后续修改。由作者整理并选择继续维护的原笔记内容，程序不自动合并或覆盖任何私人笔记，也不删除旧副本。

在已有文章上查看来源候选，再明确绑定选中的原笔记。候选按文件名或标题匹配，忽略大小写、Unicode 表示与空白差异，排除历史“博客发布”副本。只有一个候选也不会自动绑定，现有路径不会自动替换；未明确迁移的旧绑定继续工作。

重新绑定保留既有站点文件名、URL、`mediaId` 与其他技术字段。准备后仍需核对内容差异并确认提交。新导入遇到可能重复的文件名或标题会被后端拒绝，并提示改用显式绑定，避免把已发布文章再建一份。

根目录 `prebuild` 不再调用 `sync:blog`，仍保留起源同步与其他内容准备。手动兜底可用 `npm run sync:blog -- --file "<原笔记路径>" --dry-run` 预览，确认后去掉 `--dry-run`；不传 `--file` 只说明用法，不扫描历史发布目录或写文件。

手动同步仍按原文件名生成目标文件，不适合文件名已经不同的旧文章迁移；这种情况使用 Admin 的重新绑定，才能保留现有地址。

## 数据、退出与升级

配置、草稿、缓存、暂存、日志与恢复记录位于 **安装目录的 `data`**。准备和验证使用其中的隔离工作区，不改正式博客或原笔记。

关闭时先保存待写字段；保存失败或冲突时保留窗口。任务进行中可以等待完成后退出，或取消后退出。重启核对实际 Git 结果，不自动重复 commit/push。

覆盖升级保留 `data`；卸载默认保留，明确选择删除时才删除。升级前仍建议备份 data。不要为了处理准备失败而删除草稿。

## 从源码开发与打包

源码目前与 DSI-blog 共用仓库，不能只复制 desktop 目录就作为完整工程运行。

在仓库根目录安装锁定依赖后：

```powershell
npm ci
npx --no-install install-electron
```

构建环境需要 Node >=22.12.0；锁定的 Electron 44 使用 `install-electron` 安装匹配的运行文件，已安装时直接退出。打包需要准备兼容的 FFmpeg / ffprobe，并通过环境变量指定工具包根目录：

```powershell
$env:DSI_FFMPEG_ROOT = "D:\tools\ffmpeg"
$env:DSI_ADMIN_OUTPUT = "D:\build-output\DSI Admin"
npm run admin:desktop:build
```

工具包内需要 `bin/ffmpeg.exe`、`bin/ffprobe.exe` 和 `LICENSE`。最终用户不需要这个构建路径。输出目录必须与源码、笔记和已有程序数据分离；含运行 data 的解包目录不能再次用于打包。

工具准备好后，桌面开发使用独立输出和测试数据目录，避免把开发草稿带进正式安装包：

```powershell
$env:DSI_ADMIN_OUTPUT = "D:\dev-output\DSI Admin"
$env:DSI_ADMIN_DATA_ROOT = "D:\dev-data\DSI Admin\data"
npm run admin:desktop:dev
Remove-Item Env:DSI_ADMIN_DATA_ROOT
```

开发启动会先构建，再打开桌面窗口；关闭窗口后命令退出。正式打包时重新设置 `DSI_ADMIN_OUTPUT` 为干净的构建目录。

发布前最低检查：

```powershell
npm run lint
npx --no-install astro check
npm run build:astro
node scripts/verify-admin-workspace.mjs
node scripts/verify-admin-recovery.mjs
node scripts/verify-admin-desktop.mjs
```

打包后还要使用 **包内的运行工具和依赖** 检查真实文章，不能以开发机通过替代：

```powershell
$env:ELECTRON_RUN_AS_NODE = "1"
& "D:\build-output\DSI Admin\win-unpacked\DSI Admin.exe" desktop/verify-package.mjs "D:\build-output\DSI Admin\win-unpacked"
Remove-Item Env:ELECTRON_RUN_AS_NODE
```

该验证只在独立 fixture 仓库操作，不向正式博客写 commit/push。还需实际安装、升级保留数据和桌面 UI 验收。完整 `npm run build` 包含内容同步写回，不用于普通 Admin UI 检查。
